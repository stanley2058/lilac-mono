# Repository audit fixes (2026-11)

Status: approved by Stanley on 2026-11-10 and merged into `main` on 2026-11-11 (`1ac81d91`). Unchecked
items are partial or open and are listed under Residuals. Items without a recorded decision use the recommended fix
written here. Source: an 11-reviewer audit (Sol and Opus) at `f2c90667`. Line numbers refer to that
commit and may drift.

## Ground rules

- **Security boundaries are best-effort separation.** The agent owns its whole container. The harness
  keeps the agent and untrusted users from stepping on each other by accident. It is not a sandbox. Do
  not lock down behavior beyond the fix recorded for each item.
- Bash safety is a fail-open guardrail. Close the listed gaps only, with no exhaustive command audit.
- Keep each fix to its item. Record new problems found along the way under "Residuals" in your lane
  instead of fixing them.
- A change to a stored-data, wire, or protocol contract needs a MIGRATIONS.md entry. Decision D1 says
  which contract changes are approved.
- Each lane works in its own worktree and branch. It runs focused tests and the typecheck for each
  changed workspace, then `bun run check` before handing back. Web lanes also follow
  `apps/web/AGENTS.md` verification.

## Decisions

- **0-0. Security model.** See the first ground rule.
- **1-1. GitHub trust gate.** Run only for commenters who are at least repository collaborators. Accept
  `author_association` OWNER, MEMBER or COLLABORATOR from the payload. For any other value, check the
  collaborator-permission API with the installation token, because private org membership can appear
  as CONTRIBUTOR, and require write or higher. Reject everyone else with a short GitHub reply, at most
  once per issue per user. Trusted mode stays unchanged behind the gate.
- **1-2. Web fetch.** Allow only `http:` and `https:` URLs. Private and loopback hosts stay reachable,
  an accepted tradeoff under 0-0.
- **1-3. Discovery search.** In restricted mode, pin the search to the calling session and drop the
  prompt and heartbeat sources.
- **1-4. SSH remote execution.** Rework it in two steps:
  1. Merge the three copies into one module in `src/ssh`. Make the remote scripts static, pass the cwd
     and arguments as base64 JSON instead of interpolating them into heredocs, and reject control
     characters in parsed cwds.
  2. Add SSH connection multiplexing (ControlMaster/ControlPersist) and cache the remote runner on the
     host by content hash, so the 160 KB runner uploads once per version.
- **1-5. Restricted message delete.** The `surface.messages.delete` tool is the problem, not curl. In
  restricted mode, delete and edit only messages the bot authored. Other targets return
  `SurfacePermissionDenied`.
- **1-6. Bash safety.** Close the four listed gaps and keep fail-open.
- **1-7. Webhook replay.** Derive `requestDeliveryId` from `X-GitHub-Delivery` so the request-delivery
  primary key rejects replays durably. Record dedupe only after successful handling. Set
  `maxRequestBodySize`. Acknowledge before the slow GitHub API calls.
- **1-8. Release gate.** The release workflow requires a successful `ci` run for the exact SHA.
- **2. Correctness.** Fix everything listed.
- **3. Performance.** Fix everything listed. Drop Plate from the web app entirely and port the composer
  Markdown codec onto the existing mdast/remark stack.
- **4. Legacy blob migrations.** Delete the scripts, the frozen store, their tests, and their manifest
  entries. MIGRATIONS.md tells older deployments to upgrade through the last commit that has them.
- **5. Kept as designed.** The "Thinking" row and timer on turns waiting for an upload fills the gap
  before the upstream run starts. Sent attachments keep both the inline chip and the card.
- **D1. Contract changes and durable state.** Pending (default: approved where a fix needs it, each
  with a MIGRATIONS.md entry): WAL delta checkpoints, workflow cancellation outbox and joint op/wait
  journaling, webhook-derived delivery IDs, `commandId` on client receipts, a client cache projection
  version, a Redis ephemeral group and consumer reaper, periodic job retention and tool-result
  `maintain()`, and the model catalog as a data asset.
- **D2. Discord messages sent while Core is offline.** Pending (default: document only, no catch-up
  scan).
- **D3. Execution layout.** Pending (default: lanes A to I below, in two waves, merged into an
  `audit/integration` branch for review before main).

### Residual pass (2026-11-11)

change keys (R2), unconsumed steers and follow-ups requeued, bounded subscription stop, Discord reactions

  restore the transcript and native databases together (MIGRATIONS.md).

  the previous write; every current write path bumps revision.

  already ran (predates the audit).

  0.157). Oxc's React Compiler is still experimental upstream.
